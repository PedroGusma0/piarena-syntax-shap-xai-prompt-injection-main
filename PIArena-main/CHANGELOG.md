# Changelog

This project does not currently use tagged releases consistently, so this changelog is maintained as a running record of notable repository-level changes.

## Unreleased

### Added

- Added root-level guidance in [`AGENTS.md`](AGENTS.md) and [`CLAUDE.md`](CLAUDE.md) requiring implementation plans to be written under `plans/`.
- Added root docs trees for supported attacks and defenses under [`docs/attacks/`](docs/attacks/) and [`docs/defenses/`](docs/defenses/).
- Added a compact public docs page at [`docs/extending.md`](docs/extending.md) covering how to add new attacks and defenses.
- Added a docs migration and standardization plan at [`plans/docs-root-migration-and-standardization.md`](plans/docs-root-migration-and-standardization.md).
- Added merged AgentDyn benchmark assets to the vendored [`agents/agentdojo/`](agents/agentdojo/) tree, including new `shopping`, `github`, and `dailylife` suites plus the dynamic tool implementations they require.
- Added a third plugin type, XAI methods (`XAI_REGISTRY` in [`piarena/registry.py`](piarena/registry.py), `BaseXAI` in [`piarena/xai/base.py`](piarena/xai/base.py)), and a new optional `--xai`/`--xai_config`/`--limit` pipeline phase in [`main.py`](main.py) run right after the defense phase (opt-in — omitting `--xai` leaves existing behavior unchanged).
- Added the `syntaxshap` XAI method ([`piarena/xai/syntaxshap/`](piarena/xai/syntaxshap/)): adapts the [SyntaxSHAP paper](https://arxiv.org/abs/2402.09259) (originally for explaining next-token generation by autoregressive LLMs) to explain a text-classification defense's decision instead — currently `promptguard`. Reimplements the paper's syntax-tree-restricted Shapley coalition game (not a subclass of the vendored, generation-only `SyntaxExplainer`) against a binary `P(non-benign)` target, and fixes a combinatorial-explosion bug present in the original `feature_exact()` (unconditional `O(2^M)` enumeration even for the tree-restricted case) that would otherwise make explaining a whole multi-sentence `context` intractable. Supports `algorithm="syntax"` (tree-restricted) and `"shap"` (unrestricted, small texts only) — the paper's level-weighted variant (`"syntax-w"`/SyntaxSHAP-W) was implemented and then removed, since the experiment always explains with plain `"syntax"`. Full design in [`plans/xai-syntaxshap-promptguard.md`](plans/xai-syntaxshap-promptguard.md).
- Added a second, independent XAI method, `kernelshap` ([`piarena/xai/kernelshap/`](piarena/xai/kernelshap/)), coexisting with `syntaxshap` in the same `XAI_REGISTRY`: explains the same `promptguard` classifier's decision using word-level Shapley values, computed via either `captum.attr.KernelShap` or the official `shap.KernelExplainer` (`backend` config, same output contract either way). Loads the classifier directly (`AutoModelForSequenceClassification`, no HF `pipeline()` wrapper) and operates on token-id tensors so a coalition is never re-serialized to text; word-level `feature_mask` grouping comes from the tokenizer's own `.word_ids()`, so subtoken fragmentation (URLs, non-Latin scripts) never inflates the number of explained features. Explains the whole `context` as a single joint coalition game (no per-sentence decomposition — unlike `syntaxshap`, Kernel SHAP's cost is a chosen `n_samples` budget, not derived from the text's syntactic structure). Full design in [`plans/xai-kernelshap-promptguard.md`](plans/xai-kernelshap-promptguard.md).
- Added `scripts/xai_metrics.py` / [`piarena/xai/metrics.py`](piarena/xai/metrics.py): computes Fidelity(t)/acc@1 (adapted from the SyntaxSHAP paper's Eqs. 6 and 8) and an injected-span rank percentile from a `--xai` result file, and renders `shap.plots.text`/`shap.plots.bar` saliency maps via the official `shap` package. Works for either XAI method's result files — `--xai-method` (default `auto`) infers which explainer to reload from the result filename's `-{xai}-` suffix. (div@K/Eq. 7 was implemented and then removed: once the explained target is always the binary `[P(BENIGN), P(MALIGN)]` aggregate, div@K collapses algebraically to `2·|Fidelity(t)|` for every sample/threshold — redundant by construction, not merely correlated. A `spearman()` "syntax vs. syntax-w" concordance metric was also implemented and then removed along with `algorithm="syntax-w"` itself.)
- Added docs at [`docs/xai/`](docs/xai/) (index + `syntaxshap.md` + `kernelshap.md`) and an "Add A New XAI Method" section to [`docs/extending.md`](docs/extending.md).
- Vendored a trimmed, patched subset of `syntax-shap-main/syntaxshap` (masker, model-wrapper, and dependency-tree utilities only — not the generation-specific explainer/captum code) into [`piarena/xai/syntaxshap/thirdparty/`](piarena/xai/syntaxshap/thirdparty/), and added `pandas`, `cloudpickle`, `captum`, `shap`, and `matplotlib` to [`requirements.txt`](requirements.txt) (`spacy` was already listed; also run `python -m spacy download en_core_web_sm`).
- Added per-phase progress visibility to the `--xai syntaxshap` pipeline, previously silent for the entire (potentially hours-long) XAI phase: [`main.py`](main.py) now prints Attack/Defense/XAI/Evaluation phase markers with elapsed time per sample; [`piarena/xai/syntaxshap/coalition.py`](piarena/xai/syntaxshap/coalition.py)'s `compute_shapley_values` computes its exact forward-pass budget upfront (from the already-built coalition set, no extra cost) and drives a `tqdm` bar off real `get_contribution_fn` calls; [`piarena/xai/syntaxshap/classifier_explainer.py`](piarena/xai/syntaxshap/classifier_explainer.py)'s `explain_context` prints which sentence (i/N) is running before each one, since cost varies wildly between sentences. On by default via a new `"progress"` key in `SyntaxShapXAI.DEFAULT_CONFIG` ([`piarena/xai/syntaxshap/xai_syntaxshap.py`](piarena/xai/syntaxshap/xai_syntaxshap.py)).
- Added [`scripts/estimate_xai_cost.py`](scripts/estimate_xai_cost.py): estimates `--xai syntaxshap` forward-pass cost for any dataset row using only a tokenizer + spaCy (no GPU, no gated-model access) — a closed-form reimplementation of the ad-hoc cost analysis in this file's "Computational cost bottleneck" section (formula derived from, and verified against, `coalition.py`'s actual coalition-counting logic on hand-worked small cases), packaged as a reusable tool instead of a one-off scratchpad script.
- Added [`scripts/run_xai_pilot_runpod.sh`](scripts/run_xai_pilot_runpod.sh): end-to-end runbook for a single-sample `--xai syntaxshap` pilot on a RunPod GPU pod (env setup incl. auto-installing Miniconda and accepting its channel ToS non-interactively, pinned-CUDA torch install, `huggingface-cli login`, a cost-check confirmation before the expensive run, `main.py`, then `scripts/xai_metrics.py`). Tuned against and partially validated on a real `runpod/pytorch:*-cu1281-torch280-*` pod.
- Added an outline around the `injected_task`'s token span in [`scripts/xai_metrics.py`](scripts/xai_metrics.py)'s `saliency_maps.html`, layered on top of shap's own per-token value coloring (`_mark_injected_span`, a regex post-process of `shap.plots.text()`'s output keyed on its `id='_tp_<uuid>_ind_N'` per-token divs — verified against real `shap.plots.text()` HTML, not just read from its source). Each sample's header now also names the attack (`_guess_attack(args.result)`, already used for W&B grouping) so a `saliency_maps.html` opened on its own — without the `plots/<result-stem>/` path for context — still says which attack it's from.
- Added a `--xai_backend captum|shap` CLI flag to [`main.py`](main.py): a dedicated shortcut that overrides the `kernelshap` XAI plugin's `backend` config key (`xai_config["backend"]`) without needing a YAML `--config` file, wins over a `backend` set inside one if both are given. Ignored by any other `--xai` method.
- Added a per-`category` breakdown to [`scripts/xai_metrics.py`](scripts/xai_metrics.py)'s report (works for either `--xai` method, since both share this script): a new "Métricas por categoria" table in `_report.md` (and `category_summary` in `_metrics.json`) grouping samples by the dataset's `category` field (e.g. `squad_v2`'s phishing/access-denial/content-promotion/infrastructure-failure labels) — Fidelity/acc@1 at the largest requested threshold plus ASR/Utility over the whole category (same "geral" semantics as the existing overall ASR/Utility row), omitted entirely for datasets without a `category` field. Each `saliency_maps.html` sample header (and the standalone per-sample PNGs some analyses export from it) now also names the category alongside the attack, so it doesn't only live in surrounding prose.
- Added [`scripts/run_with_gpu_load_log.sh`](scripts/run_with_gpu_load_log.sh): a generic wrapper (not `--xai`-specific — works for any command, e.g. `main.py` itself) that polls `nvidia-smi` in the background while the wrapped command runs and, once it finishes, writes a per-GPU peak/mean utilization and memory summary alongside the raw CSV — for recording GPU load per run (e.g. for a report/advisor) rather than watching it live (`watch -n 1 nvidia-smi` / `nvitop` cover that instead).
- Added [`scripts/xai_compare_backends.py`](scripts/xai_compare_backends.py): compares Kernel SHAP's two computation backends (`captum.attr.KernelShap` vs. the official `shap.KernelExplainer`) on the same samples, reading two already-computed `main.py --xai kernelshap` result files (one per backend) directly — no model reload, pure JSON + numpy/scipy, same spirit as [`piarena/xai/metrics.py`](piarena/xai/metrics.py) and modeled on [`scripts/xai_compare_fidelity.py`](scripts/xai_compare_fidelity.py)'s structure. Computes, per common sample and aggregated: Pearson correlation of the raw signed Shapley values, Spearman rank correlation of `|value|` (the direct analogue of the removed `syntax` vs. `syntax-w` `spearman()` metric, this time correlating backend instead of algorithm — see `piarena/xai/metrics.py`'s trailing comment), sign agreement, top-k word overlap (`top_t_mask`, reused from `piarena/xai/metrics.py`), and the gap between the two backends' `injected_span_percentile` (also reused). Writes `backend_agreement_metrics.json`/`_report.md`/a Spearman-rho histogram PNG, plus optional W&B logging (`--no-wandb` to disable). Since `main.py`'s result filename doesn't encode `backend`, producing the two clean input files requires giving each backend run its own `--name` — documented in [`docs/xai/kernelshap.md`](docs/xai/kernelshap.md)'s new "Comparing backends" section, along with the full rationale in [`plans/xai-kernelshap-backend-agreement.md`](plans/xai-kernelshap-backend-agreement.md).

### Fixed

- Fixed [`scripts/xai_metrics.py`](scripts/xai_metrics.py) crashing with `AttributeError: 'NoneType' object has no attribute 'get'` on any sample the defense didn't block: `main.py` sets `xai_result` to an explicit `None` (not an absent key) for those samples, so `sample.get("xai_result", {})` returned that `None` instead of falling back to `{}` — fixed in both `compute_one()` and `_render_plots()` by using `(sample.get("xai_result") or {})` instead.
- Fixed `scripts/xai_metrics.py`'s plot output (`plots/saliency_maps.html`, `fidelity_acc_bars.png`, `alignment_histogram.png`) silently overwriting itself across attacks: unlike `<result-stem>_metrics.json`/`_report.md`, the `plots/` directory wasn't namespaced by the result file's stem, so running the script once per attack against the same `--name` (as `run_kernelshap_squad_v2_4attacks.sh`/`run_syntaxshap_squad_v2_4attacks.sh` do) left only the last attack's plots on disk. Plots now live under `plots/<result-stem>/`.
- Fixed every token in `scripts/xai_metrics.py`'s `saliency_maps.html` rendering with no background color ("transparent" words) and `shap.plots.text()`'s "base value → f(inputs)" flow bar rendering as a dense black smear: both traced to a real `shap<0.52.0` + `numpy>=2.0` compatibility bug (numpy 2.0 changed `repr(np.float64(x))` to the string `"np.float64(x)"`, breaking shap's text-plot `rgb()`/`rgba()` color-string formatting — fixed upstream only in shap 0.52.0, which requires Python ≥3.12 and so isn't installable in this project's Python 3.10 env; `pip`'s Python-3.10-compatible ceiling is `shap==0.49.1`, still affected). An invalid CSS value like `rgba(np.float64(255.0), ...)` is silently dropped by the browser (no background — the "transparent" words) or falls back to a default black stroke (the flow bar's per-token wedges — the black smear). `_fix_numpy_scalar_colors()` strips the `np.float64(...)` wrapper from the rendered HTML before writing it out, so this no longer depends on which `shap` version is installed. Also removes the "Carregar mais amostras" chunked-loading button (`_load_more_button_html`, `_SAMPLES_PER_CHUNK`) — every explained sample now renders directly in one page.
- Fixed [`main.py`](main.py) loading two full copies of the default backend LLM (`Qwen/Qwen3-4B-Instruct-2507`) onto the GPU at once: `llm_judge`/`llm_judge_batch` ([`piarena/evaluations/llm_judge.py`](piarena/evaluations/llm_judge.py)) already accept an `llm=` param specifically to reuse an already-loaded instance instead of loading their own global `judge_llm`, but the evaluator calls in `main.py`'s main loop never passed it — now they do. Also added `torch.cuda.empty_cache()` at the end of every sample in that loop: Attack/Defense/XAI/Evaluation each allocate tensors of sample-dependent shapes (varying text length, kernelshap's `n_samples` growing with word count, ...), and PyTorch's caching allocator doesn't release freed memory on its own, so across many samples with varying shapes the "reserved" pool fragments and grows even without a true per-sample leak — observed as a `CUDA out of memory` crash partway through a `dolly_summarization` run (63/200 samples in) despite a 24GB GPU, with a much smaller amount actually live at any one time.
- Fixed [`piarena/xai/kernelshap/classifier_explainer.py`](piarena/xai/kernelshap/classifier_explainer.py)'s `ClassifierKernelExplainer` silently truncating `context` to `tokenizer.model_max_length` (~512 tokens for `Prompt-Guard-86M`) by default before explaining it, while [`PromptGuardDefense.execute`](piarena/defenses/promptguard/defense_promptguard.py) — which actually produces `detect_flag` — calls the HF `pipeline` with no truncation at all and scores the full `context`. For long contexts where the attack appended the injected task past that cutoff (common on long Dolly `closed_qa`/Wikipedia-style contexts), the defense correctly saw the injection and blocked, but the XAI module then explained only the truncated prefix, which never contained it — producing a misleading `predicted_label`/`p_malign` and `injected_span: null` for a sample the defense had correctly flagged (confirmed against real saved results in `kernelshap_dolly_closed_qa_captum/*.json`). `max_length=None` (the default) now means no truncation at all, matching the defense's own scoring exactly; passing an explicit `max_length` still truncates (for cost control) but now logs a warning, since the resulting explanation may not cover what the defense actually saw. Also consolidated `explain_context`'s `injected_span` localization to reuse the tokenization `_explain_text` already computed instead of re-tokenizing `context` a second time. See [`plans/xai-kernelshap-truncation-fix.md`](plans/xai-kernelshap-truncation-fix.md).
